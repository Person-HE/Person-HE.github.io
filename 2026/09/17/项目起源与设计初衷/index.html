项目起源与设计初衷：知源 Flow 社区的来龙去脉

发表于2026-09-17|更新于2026-09-28|项目感悟
|浏览量:

这篇也重写。旧版发出去之后我把仓库从头读了一遍，读完发现起源还是那个起源，但里面几处我当时讲高了，什么"完整三防""吊销机制"，还有 git 历史这件事我一直没提过。先讲起源，再讲哪些是真想清楚了、哪些是后来才看明白的，看明白得晚的也不少。

为什么做这个

我之前写过不少练手项目，登录、增删改查、表单管理、SSM 单体，全是那种一眼看得穿的管理系统。真正让我下决心重做一个的，不是又想写新项目了，是发现手里这些东西撑不起一个后端该有的厚度，简历上排不开，面试讲不出第二层。

起点是 QQ 频道，圈子加分区那套组织方式，我觉得那个结构天然适合把人放在一起说话。后来刷抖音，看评论区，算法把爱好相同的人聚到同一条内容底下，满屏都是"有人懂我""终于有真实反馈了"这类话。我就想，把有共鸣的人放进同一个圈子，"懂我"这件事能不能不用用户自己去茫茫内容里捞，让它自己发生。

于是有了 zhiyuan_Flow，现在叫知源 Flow。

为什么不选电商不选博客，选社区——因为我真的天天刷社区。哪个环节让人想关掉 App 我自己就是那个想关掉的人，不需要"研究用户"。也因此第一天就知道三件事：圈子必须是核心不是帖子，没有归属感的平台迟早一锅粥；开放 UGC 没审核就是灾难，AI 审核必须有；没人愿意反复刷新看有没有人回复自己，实时通知和私聊是留存的命脉。这三条后来真成了骨架。

形态是怎么收敛的

V1 那版功能上像 QQ 频子的低配复刻：圈子、分区、发帖、评论、点赞、聊天，做了 55 个 API。功能齐，但没有灵魂，它就是又一个论坛。

V3.0 想清楚的不是加功能，是这社区到底在帮人做什么——帮情绪表达和情绪共鸣。所以：列表变地图，首页广场帖子区全是按情绪分布的节点；帖子改叫心声，评论区改叫共鸣墙，根评论是心声回应，子回复是连线；点赞旁边加了抱抱，比点赞轻，带温度，计入共鸣数；角色砍到只剩圈主和成员，管理员和贡献度删了；分区只剩公开和匿名两种，而且匿名由分区决定，用户不手选，匿名是分区给的安全感不是开关；情绪枚举十类，joy sorrow abstract secret comfort memory gratitude anger anxiety neutral。

进这个平台第一件事不是发帖，是看情绪地图，或者建圈找圈。所有内容都归属某个圈子。

还有一个决定是所有互动都得有反馈链路，点赞评论被踢公告，全推通知，WebSocket 实时加数据库兜底，这条是产品体验的底线。AI 审核那个也纠结过，最后定成只做兜底不做主审，规则层先过关键词长度频率，规则没把握的才送 AI，AI 是补漏员不是判官，整条审核链藏在后端，用户侧看不见。

git 里没有过程

这件事我一直没讲过。这个仓库一共三条提交。第一条 2026-05-22，一条把之前所有历史抹平、清掉敏感数据的大快照；第二条 2026-06-28，修通知系统、AI 审核、图片上传、帖子交互那批 bug，顺手删了网关和 microservice 残留；第三条 2026-09-17，V3.0 release。中间隔了三十七天、八十一天，过程全在本地，没有中间提交。

所以这个仓库只看得到三个快照，看不到我一天干了什么。面试里我说"这个项目我是分阶段重构着推的，git 里保留了三个大节点，中间过程没提交"，不丢人，编"我们每天提交"才是一问就穿。

用户的一天，我设计的时候真就是这么走的

早上九点，张同学打开 App 首页是情绪地图，点开一条聊 Redis 持久化的心声，进共鸣墙看完抱了一下，这个抱抱异步推给作者王同学，链路走到缓存、通知、落库。上午十一点他在 Java 圈子发了条求助，先过规则审核再异步送 AI 兜底，结果落审计表，用户全程不知道审核存在。下午两点王同学收到 WS 推的评论通知，点通知直达帖子，顺手发起私聊，私信只走 WebSocket 不留 HTTP 兜底，这条后面讲为什么。晚上八点张同学刷到共鸣的心声生成分享链接，帖子评论圈子三类都能分享。晚上十一点圈主发公告，在线的 WS 推，离线下次拉。凌晨两点他睡不着，打开情绪陪伴，SSE 一个字一个字往外蹦，说到"觉得自己好没用"的时候危机词闸门先接住，不送模型，聊十轮 Redis 还记着上下文。

这一天下单的是产品形态，背后每一段都对应仓库里真实存在的链路，画得出来的那种。

讲高了的地方

起源那篇里我写过"多级缓存做了完整三防""JWT 双 Token 带吊销"。逐行读完自己的代码之后：三防的件是真有——空值占位、分布式锁、TTL 加抖动，A/B 数字也是真的；但 L1 根本不吃传入的 TTL，锁释放是个裸 delete 不校验持有者，黑名单写了没人读，refresh 不轮换。"吊销"这个词我只做了一半，当时写成一个完成态的设计决策，其实黑名单只写不读不是取舍，是没做完。这种话在面试里被拆一次，比少写三个亮点伤得多。

还有一个是形态演变里写的"AI 审核五层降级"，链路的层级是真配了，但 MQ 拓扑四个事件三个没有生产者，审核在默认配置下走的全是同步降级。我写"三件套是我最满意的设计"的时候，它有一半是没接线的。自己最满意的地方恰恰最该先拉出来重验一遍，这个我承认是吃了亏才懂的。

还没做和不会碰的

搜索就是 MySQL LIKE 加索引，没上 Elasticsearch，我这个量级够用，但我知道天花板低，不会把它写成"引入了 ES"。容量压测（SLA-QPS）要独立施压机，本机同机只能证机制和尾延迟，这个数还没测到，就不编。

命名这事最后说一嘴。最早叫 community-platform，很工程师，很没灵魂，后来改成知源 Flow，取"知其源、明其流"，GitHub 上一眼看出来。旧文章里那个"致远"是更早的版本，V3.0 之后统一了。
