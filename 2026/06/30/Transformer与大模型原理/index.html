Transformer与大模型原理

发表于2026-06-30|更新于2026-06-30|AI热门
|浏览量:

一、Transformer之前：RNN的困境

在Transformer出现之前，处理序列数据（如文本）的主流方法是RNN（循环神经网络）。

RNN的问题：像一个人逐字读文章

想象你读一句话："我今天很开心因为考试通过了。"

RNN的阅读方式：一个字一个字读，读完"我"，记住一点信息；读完"今天"，再更新记忆……直到读完最后一个字。

问题：

  1. 读得太慢：必须按顺序读，不能并行
  2. 记性不好：句子太长时，前面的内容会被"遗忘"
  3. 训练困难：长序列的梯度容易消失或爆炸

为什么RNN不能并行？

解答： 因为RNN的计算是链式依赖的。要计算第10个字的状态，必须先知道第9个字的状态；要知道第9个，必须先知道第8个……这就像接力赛，第10棒必须等第9棒跑完。而Transformer打破了这种依赖——它让模型一次性看到所有字，然后自己决定哪些字之间有关系。

二、Transformer的核心创新：注意力机制

Transformer的论文标题是《Attention Is All You Need》（注意力就是你所需要的一切）。这个标题很霸气——它在说：不需要RNN那种复杂的顺序计算，只靠"注意力"就能做好一切。

2.1 注意力机制：像人类阅读时的"重点关注"

当你读这句话时：

"小明把苹果给了小红，因为她想吃。"

你的大脑会自动建立关联：

  • "她" → 指"小红"（不是小明）
  • "苹果" → 是"给"的对象
  • "想吃" → 是"给"的原因

注意力机制就是让模型自动学习这些关联。

2.2 自注意力（Self-Attention）

自注意力的核心思想：每个词都要和其他所有词"对对碰"，看看谁和谁有关系。

计算过程（简化版）：

Q、K、V到底是什么？能不能再通俗点？

解答： 用图书馆比喻：

  • Q (Query/查询) = 你写的问题清单（"我想了解Transformer原理"）
  • K (Key/键) = 每本书的目录标签（书名、章节标题）
  • V (Value/值) = 书里的具体内容（你实际要读的内容）

注意力计算 = 用问题清单(Q)匹配目录标签(K)，找到最相关的书，然后阅读内容(V)。
自注意力 = 每本书都写了自己的问题清单（不只是你在问），互相匹配找到关联。

2.3 交叉注意力（Cross-Attention）

交叉注意力发生在编码器-解码器结构中，用于机器翻译等任务。

自注意力和交叉注意力有什么区别？

解答： 自注意力是"句内关系"（句子里的词互相看），交叉注意力是"句间关系"（一个句子的词看另一个句子的词）。就像：

  • 自注意力 = 读一句话时，理解句内词语的关联
  • 交叉注意力 = 读双语对照材料时，理解中英文词语的对应关系

三、为什么Transformer比RNN快？

关键差异：并行计算

结果：

  • RNN训练1000个token的句子：像单线程程序，逐个计算
  • Transformer训练1000个token的句子：像多核CPU，同时计算所有位置的注意力

这让Transformer可以大规模扩展——模型可以更深、数据可以更多，而RNN根本做不到。

小白问： Transformer就没有缺点吗？

解答： 有！最大的缺点是计算复杂度随序列长度平方增长（O(n²)）。也就是说，1000个token的计算量是100个token的100倍（不是10倍）。这导致Transformer处理超长文本（如整本书）时很吃力。解决方案包括：稀疏注意力、滑动窗口注意力、线性注意力等变体。

四、大模型核心概念详解

4.1 Token：模型的"乐高积木"

大模型不直接理解文字，它把文字切成Token（词元）。

为什么重要？

  • API按Token计费（输入+输出都算）
  • 上下文窗口的大小用Token衡量
  • 中文通常1个字 = 1-2个Token，比英文"贵"

4.2 上下文窗口（Context Window）

模型一次能处理的最大Token数。

模型 上下文窗口 大约能放多少字
GPT-3.5-turbo 16K 约1万字
GPT-4o 128K 约8万字
Claude 3.5 200K 约13万字
DeepSeek-V3 128K 约8万字

注意： 上下文窗口是输入+输出的总和。你输入了100K Token，模型最多只能输出28K Token（以128K模型为例）。

小白问： 上下文窗口越大越好吗？

解答： 不一定。更大的窗口意味着：

  • 优点：能处理更长的文档、更长的对话历史
  • 缺点：计算量更大（成本更高）、可能出现"中间遗忘"（注意力集中在开头和结尾，中间内容被忽略）
    对于大多数应用，16K-128K足够了。

4.3 幻觉（Hallucination）

模型编造不存在的信息，而且说得像真的一样。

幻觉类型：

  • 事实幻觉：编造不存在的人物、事件
  • 数字幻觉：编造具体数字（"增长了47.3%"）
  • 引用幻觉：编造不存在的论文引用

解决方案：

  1. RAG（检索增强生成）：让模型基于真实资料回答
  2. 事实核查：用程序验证关键信息
  3. 降低Temperature：减少随机性
  4. 明确约束：告诉模型"不知道就说不知道"

4.4 温度参数（Temperature）

控制模型输出的随机性。

比喻： Temperature就像选餐厅：

  • 低Temperature = 总去评分最高的那家（稳妥但缺少惊喜）
  • 高Temperature = 偶尔也去评分一般的新餐厅试试（有风险但可能有惊喜）

适用场景：

Temperature 适用场景
0 - 0.3 代码生成、数据提取、数学计算
0.3 - 0.7 翻译、摘要、问答
0.7 - 1.0 对话、写作、头脑风暴
1.0 - 1.5 创意写作、诗歌生成

Temperature是怎么控制随机性的？

解答： 模型生成每个词时，会给所有候选词打分（概率分布）。Temperature调整这个概率分布的"尖锐程度"：

  • Temperature低 → 概率分布尖锐 → 高概率词更容易被选中 → 输出确定
  • Temperature高 → 概率分布平坦 → 低概率词也有机会被选中 → 输出随机

就像掷骰子：正常骰子每个面概率1/6。Temperature低时，某个面的概率变成90%；Temperature高时，概率更接近均匀。
