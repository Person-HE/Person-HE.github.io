第一道挡"未登录"。

第二道挡"权限不够"。

第三道挡"业务不允许"。

三道之间没有任何冗余 —— Filter 不知道业务规则，AOP 不知道状态机，Service 不知道 Token 怎么解析。分工清晰，单点修改不影响其他层。

5. 章节五：多级缓存三防链路图

L1 Caffeine + L2 Redis + L3 DB。三防：穿透 / 击穿 / 雪崩。

flowchart TD
    Start["MultiLevelCache.get(key)"]

    L1["L1: Caffeine (JVM 堆内)
- local cache: max-size 10000, expire 5 min
- hot cache: max-size 50000, expire 10 min"]
    L1Hit{命中?}
    L1Return[return value]

    L2["L2: Redis"]
    L2Hit{命中?}
    L2Write[write L1]
    L2Return[return]

    NullPlaceholder{NULL_PLACEHOLDER?}
    NullReturn[return null]

    Lock["SETNX lock_key"]
    LockSuccess{成功?}
    LockFail["sleep 50ms retry"]

    L3["L3: MySQL"]
    L3Has{有值?}
    L3Null["Redis SET (TTL + jitter, NULL_PH)"]
    L3Value["Redis SET (TTL + jitter, write L1)"]
    L3ReturnNull[return null]
    L3ReturnValue[return value]

    Lua["Lua 释放锁:
if redis.call('get', KEYS[1]) == ARGV[1]
then return redis.call('del', KEYS[1])
else return 0 end"]

    Start --> L1
    L1 --> L1Hit
    L1Hit -->|hit| L1Return
    L1Hit -->|miss| L2
    L2 --> L2Hit
    L2Hit -->|hit| L2Write --> L2Return
    L2Hit -->|miss| NullPlaceholder
    NullPlaceholder -->|yes| NullReturn
    NullPlaceholder -->|no| Lock
    Lock --> LockSuccess
    LockSuccess -->|成功| L3
    LockSuccess -->|失败| LockFail --> Lock
    L3 --> L3Has
    L3Has -->|null| L3Null --> L3ReturnNull
    L3Has -->|有值| L3Value --> L3ReturnValue
    L3ReturnNull --> Lua
    L3ReturnValue --> Lua

三防对应表

风险 表现 防护手段 代码位置
穿透 不存在的 key 反复打 DB NULL_PLACEHOLDER 标记空值 MultiLevelCache
击穿 热点 key 过期瞬间并发打 DB SETNX 分布式锁 + 双重检查 tryAcquireLock
雪崩 大量 key 同时过期 applyJitter 给 TTL 加随机抖动 setWithJitter

MQ 启停

关键暗知识：MQ 默认是关的。本地开发开 Docker 才能跑，CI 跑单测时关掉避免误连。配置开关 + 业务降级是个人项目接入 MQ 的标准姿势 —— 不要假设中间件永远在线。
